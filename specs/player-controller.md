# プレイヤー試作

F5で `scenes/game.tscn` を実行。A/Dまたは左右矢印で走り、Zで接着を切断し、接触面から短く蹴り出す。床離脱直後のコヨーテタイムを除き、空中のZは切断だけを行う。Rでステージを再生成する。既存マップの閲覧は `scenes/map_preview.tscn` をF6で実行する。

`CharacterBody2D` の足元を原点とし、幅20・高さ52 pxの固定カプセルで衝突する。正規化済みTeto画像を256 pxセルで切り出し、0.3125倍で表示。待機は6コマ/6 fps、走りは8コマ/12 fpsでループ。空中はjumpの2・3・5番（0始まり）を上昇・頂点・下降に割り当て、着地時は6番を短く表示する。描画は移動や当たり判定に影響しない。

左右の意図速度と外部速度を別々に保持し、重力・蹴り出しは外部速度へ加算。地上速度220 px/s、重力1100 px/s²、蹴り出し260 px/s。空中の入力加速度は弱める。床・壁・天井への接触中、または床離脱直後のコヨーテタイム中に蹴り出せる。同じ接触中の連打・長押しや空中ジャンプは不可。外部速度は衝突面に沿って整理し、入力速度は投影後の横成分だけを保持する。入力速度の縦成分は常にゼロとし、衝突で生じる上向き成分を持ち越さない。ガムの張力は `apply_external_force(force, delta)` で積分する。

カメラはマップ範囲内で追従する。ガムと軽・重の物理箱を実装。方向キーで常時方向を指定し、X押下で先端を発射、到達して接着した次更新から自動収縮する。接着中は下で弛緩・延長、弛緩中の上で手動短縮、Xで自動収縮する。方向指定・発射中も左右移動を継続する。詳細は `bungee-gum-prototype.md` を参照。敵・クリア判定は未実装。全ステージ攻略の合格判定は未完了。

`Game` が毎物理ティック、接続入力→張力→`Player.simulate(delta)`→カメラ・表示の順に更新する。Player自身は `_physics_process` を持たず二重更新を避ける。カメラは移動後の位置を追う。

検証: `Godot --headless --path gd-bungee-gum --log-file /tmp/player-check.log --script res://tools/verify_player.gd`。

接地中の外部速度は床の接線方向に `ground_friction`（初期値900 px/s²）でゼロへ減速する。300 px/sの外部速度は約0.33秒で停止する。着地したティックから適用し、左右入力・照準・接続の有無に依存しない。空中と床から離れる蹴り出しには適用せず、入力速度の加減速は従来どおり別に処理する。

調整値は共有設定 `resources/game_settings.tres` のPlayer Movementで編集する。編集手順と表示設定は `game-settings.md` を参照。

接地キックの使用可否は、床に接触しているティック、または床・壁・天井すべてに接触していないティックで回復する。壁に接触し続けて着地しても床キックを再使用できる。壁／天井だけの継続接触では回復せず、コヨーテタイム外の空中のZ入力は加速しない。

床離脱時の入力猶予（コヨーテタイム）は共有設定`coyote_time`（初期値0.10秒、0で無効）で制御する。床接触中に残り時間を更新し、非接地ティックで時間を減らす。非接触でも残り時間があれば真上へ一度だけ接地キックを加算できる。床・壁・天井でのキックを含め、成功したキックは猶予を消費する。壁／天井の離脱では猶予を補充せず、通常ジャンプ後の二段ジャンプや入力先行受付は設けない。Zのガム切断はキック判定より先に行う。

コヨーテキック直前には、離床後に重力で増えた速度のうち、下向き成分だけを補正する。補正量は現在の外部速度の同方向成分以下に制限し、真上への蹴り出しを加算する。横速度・上向きの勢い・重力分を超えるガムや衝突由来の落下速度は保持する。重力の補正用速度も実際の衝突法線で投影し、地形が既に取り除いた分を補正に再利用しない。床接触で補正用速度をリセットし、猶予切れまたはキック成功で消去する。床キックも真上へ加算し、壁・天井の接触キックは接触面からの既存の方向を使う。接地法線は接触判定・衝突処理・摩擦に使用し、床・コヨーテのキック方向には使用しない。

## ブロック接触と圧縮

入力・重力・キックを速度へ反映した後、`move_and_slide()`より先に剛体との接触インパルスを解く。プレイヤー本体の幅20・高さ52 pxカプセルは保持し、接触用のカプセルだけを`contact_clearance`（初期値0.75 px）広げる。2 px以内の凍結していないレイヤー4剛体について、各有効形状との`collide_and_get_contacts()`で接触点・法線・深度を取得する。この形状判定ではライブの衝突マスクを変更しない。ブロックが1個でも接触応答を行い、両側の深いめり込みを開始条件にしない。

接触点速度には剛体の並進・角速度を含め、質量・重心・慣性は物理サーバーの状態から取得する。反発係数は`contact_restitution`（0.1）で、接近速度30 px/s以下では反発分を加えない。分離目標速度はmax(接触深度−0.05 px,0)×`contact_penetration_response`（0.8）÷deltaを`contact_separation_speed`（120 px/s）で制限した値に、衝撃時の反発分を加える。

複数接触は8回の逐次インパルス解法で連動させる。各接触の有効逆質量はプレイヤー逆質量＋剛体逆質量＋接触レバー腕の法線に対する外積の二乗×逆慣性。更新済みの両端速度から接近速度を再計算し、累積インパルスを非負に制限する。剛体には実接触点でインパルスを与え、同じ運動量をプレイヤーから差し引く。すでに十分な分離速度がある接触には追加しない。ブロックの位置・回転を直接書き換えず、力を受けるsleep中の剛体を起こす。ガムの張力・自然長・接着点は保持する。

移動後に地形へのめり込みが残り、近くに動く剛体がある場合は、剛体レイヤーを除いたゼロ移動の`body_test_motion`で地形復元量を調べる。0.01 px以上なら、余白`safe_margin+0.25 px`で最大8回、物理エンジンの復元結果を適用する。補正方向の剛体へ質量×（補正距離÷delta＋接近速度）の反作用を返す。地形補正を実施した場合だけ地形対象の微小移動で支持判定を更新する。接触インパルス・移動前後の法線・補正後の床法線で速度を整理し、接地した落下速度の蓄積を防ぐ。

`Pinning Diagnostics`の`CONTACT_IMPULSE`は各接触の相手・位置・法線・深度、接近／分離目標速度、合計インパルス、物理サーバー上の剛体速度の前後を記録する。`COMPRESSION_RECOVERED`は地形補正量を記録する。それぞれ30物理ティック間隔に制限する。

`tools/verify_compression.gd`は左右の壁への継続圧力、質量差・回転、ガム収縮、既に狭い隙間に入った状態、1 kg／6 kgブロック間のsleep状態からの応答と継続的な両側3000の力を検証する。単体衝突の即時反作用、速度整理前の運動量保存、偏心衝突の回転、分離中の追加反発抑制、圧力解除後の接地・キック脱出を確認する。`-- --two-block-only`で剛体間と単体衝突だけを実行できる。
