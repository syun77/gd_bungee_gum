# ファミリーレストラン・ステージのマップ

## 開き方

Godotプロジェクトは `gd-bungee-gum/project.godot`。F5は `scenes/game.tscn` のプレイ、`scenes/stages/theater_stage.tscn` のF6はステージ単体。`scenes/map_preview.tscn` をF6で開くと矢印でパン、1〜6で区画、Tabで全景、Homeで入口へ移る。

160 × 24セル、32pxグリッド、5120 × 768px。ポップなファミリーレストランのクリーム陶板・コーラル・ミントの棚板を使用する。地形と一方通行床は保存されたシーン上で編集できる。生成元の正本は `scripts/stage_layout.gd`。

## 現在の運動性能に合わせた寸法

`resources/game_settings.tres` を読み込んだ値を基準とする。値を変更せず地形を設計した。

| 項目 | 値／配置基準 |
| --- | --- |
| 走行 | 220px/s、地上加速1600、空中加速350px/s² |
| 床の蹴り出し | 400px/s、重力1100px/s² |
| 理論上の上昇量 | 約72.7px（連続時間、静止床から） |
| 実コントローラの60Hz測定 | 約69.48px上昇、同じ高さへ戻る滞空約0.70秒 |
| 助走済みの同高度水平移動 | 約154px。空中加速・体幅・コヨーテによって変わるため、必須の大ギャップ設計には使わない |
| 蹴り出し用の段差 | 64px。一方通行床は真下から上がれる重なりを持たせる |
| ガム用の登り | 128px。静止床の蹴り出しだけでは届かない |
| 射程／接続上限 | 240px／400px。接続上限を発射射程と混同しない |
| 基準の上向き接着 | 足元から梁下面まで256px、胸元原点（足元−34px）から222px。射程内に18px残す |
| ガム | ばね35、減衰9、収縮180px/s、最短36px、最大張力2800。実際の登りはこの設定で検証する |

ガムの支点は厚い地形の梁。薄いミントの一方通行床はガムを通過させ、上昇後の着地点を担当する。低い梁と上段床の間にも52pxのカプセルと64px蹴り出しが収まる空間を確保する。斜め撃ちは射程の垂直成分が小さくなるため、基準ルートは真上への発射で成立させる。蹴り出してからの斜め接着や高所ルートは応用として残す。

## 6区画の構成

全区画に広い回復床を置く。落ちたら直ちに全体リスタートする構成にはせず、その区画の下側から上り直せる。各区画出口は下の床より高く、走り抜けだけでは突破できない。敵・投射物・区画チェックポイント・出口クリア判定はこの地形には含めない。

| 区画 | セルX範囲 | 基準ルートと一方通行床 |
| --- | --- | --- |
| 01 CONTACT | 2–25 | 床y640。64px上の短い棚で蹴り出しを試せる。x576から梁下面y384へ接着し、棚y512へ128px上昇、広い出口床へ移る |
| 02 SWING | 26–53 | 高い梁と上側の棚を使える近道、下にはy704の回復床。x1472で棚y576へ引き上げ、64px蹴り出してy512へ復帰 |
| 03 LIGHT CARGO | 54–79 | y640の広い箱操作床。軽箱はx1952。x2240でy512へ上がり、64pxの棚を経由して出口y448へ |
| 04 HEAVY ANCHOR | 80–105 | 高所の重箱受けと段違いの上側ルート。下はy704。x3136でy576へ上がり、64px蹴り出して出口y512へ |
| 05 REDIRECT | 106–131 | y640の作業床と64pxの遮蔽2つ。x3904で梁に接着し、棚と出口y512へ上昇。弾を実装するための空間のみ用意 |
| 06 EXIT | 132–157 | y704からx4608でy576へ、蹴り出してy512へ。x4736へ移ると下の梁が上向き射線から外れる。2本目の梁で棚y384へ上がり、x4944の出口へ |

一方通行床は15本・計76セル。通過して上から乗れる面として、回復、引き上げ後の落ち着き、次の蹴り出し、上側の任意ルートへ使う。Downはガムの弛緩操作のままで、床の下抜け操作は追加しない。

## 編集と再生成

- `stage_layout.gd`: `TERRAIN`、`ONE_WAY_FLOORS`、マーカー、基準ルートの登り地点を定義する。
- `TerrainTiles`: 通常地形の画像。衝突は無効。
- `Terrain`: 27個の矩形による物理レイヤー1の静的地形。通常地形を手編集するときは画像・矩形・対応するRimを同時に直す。
- `OneWayPlatforms`: source ID 1、ネイティブ一方向衝突が有効。タイルの描画・消去だけで判定が更新される。
- `Background` / `BackgroundIron` / `Signs`: 衝突なし。Labelは共通デバッグThemeを継承する。
- `PlacementMarkers`: プレイヤー、箱、将来の投射装置・標的、出口、区画の目印。Gameは箱とプレイヤーの初期位置を対応マーカーから取得する。

```sh
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --path gd-bungee-gum --log-file /tmp/map-build.log --script res://tools/build_theater_stage.gd
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --path gd-bungee-gum --log-file /tmp/map-check.log --fixed-fps 60 --script res://tools/verify_theater_stage.gd
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --path gd-bungee-gum --log-file /tmp/route-check.log --fixed-fps 60 --script res://tools/verify_stage_route.gd
```

再生成はマップとTileSetを上書きする。持続させる配置変更はまず `stage_layout.gd` を更新する。

## 検証範囲

`verify_theater_stage.gd` は全160×24セルで描画と静的判定を照合し、1212通常地形セル・27矩形・76一方通行セル・59ガム凸角・マーカーの空間を検査する。

`verify_stage_route.gd` は実Game（4個の箱を含む）を起動し、保存済み設定で入口から出口まで移動する。左右入力とZ、実際の `Gum.fire` →収縮→解除を用い、開始後の位置変更、速度注入、長射程設定を使わない。7回の128pxガム登りと64pxの蹴り出し、遮蔽・箱の通過を含む。各ガム登りで通常の蹴り出しだけでは届かないことも確認する。物理テストではGameの自動更新を止め、同じガム→プレイヤー順序で固定更新する。

到達可能性の基準はこの下側ルート。上側ショートカットの最短手順・連続スイングの難易度とプレイ感は自動踏破の保証対象ではない。ローカルGodot4.5.1で確認し、操作パラメータを変えたら踏破検査を再実行する。
