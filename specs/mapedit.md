# MapEdit

macOS 用のステージ配置エディタを `tools/mapedit/` に置く。Godot の編集中のステージを取り込み、プレイに関わる配置を一枚のキャンバスで編集して同じステージへ戻す。保存済みステージの正本は Godot シーンとする。

## 実装環境

Swift + AppKit を使用する。キャンバスは単一のカスタム NSView とし、描画とセル判定で同じ座標変換を使う。AppKit の入力イベント、NSPasteboard、UndoManager を利用し、交換データは Codable のモデルで扱う。Godot 側は `addons/mapedit/` の GDScript EditorPlugin が交換と反映を担当する。

## 編集画面

- 地形、片方向床、ガムアンカー、バリア、トゲ、食べ物、スタート・ゴールなどを同じ 32px グリッドに表示する。右ペインのスクロール可能な 2 列のグリッドパレットで配置種別またはマーカーを選び、下のタイル欄でバリエーションを選ぶ。選んだ種別を強調表示し、重複セルでも消去対象を選択中の種別に限定する。
- タイルは種別ごとに同じ 1 セルの正方形で描き、重複セルでは選択中の種別を優先して表示する。パレットの名前の前の ■ はマップと同じ種別色を使う。スタートは緑、ゴールはピンク、チェックポイントはオレンジで、これらのマーカーは画面上で直径 14pt とする。
- 左クリック・ドラッグで配置、右クリック・ドラッグで消去する。ドラッグの通過セルを補間し、一筆を一回の Undo にまとめる。マーカーはドラッグ移動し、既存のピクセル位置とセル内オフセットを保持する。
- パン、カーソルを基準としたズーム、全体表示、セル座標表示を備える。下部のミニマップは全体を縦横比を保って表示し、表示範囲とステージの重なりを矩形で示す。マップ内のクリックや左ドラッグで、倍率を保ったままポインターの地点をキャンバス中央に移す。ドラッグが地図の外に出た場合は地図端まで移動する。装飾レイヤーは交換対象から除外する。

終了時に現在の配置、カメラの倍率とスクロール位置、手動保存先、変更判定に使う基準を macOS の Application Support 内のセッション JSON に原子的に保存し、次回起動時に検証して復元する。Undo 履歴はセッションに含めない。自動保存が失敗した場合はエラーを表示して終了を取り消す。

## Godot との往復

1. Godot の専用メニュー「MapEdit にコピー」で、編集中のステージのゲームプレイ配置をバージョン付き UTF-8 JSON としてコピーする。MapEdit で貼り付けて編集し、「Godot に送る」で JSON を 127.0.0.1:47653 のエディタープラグインに送る。Godot 側で検証、差分確認、Undo を処理する。直接送信は確認結果を待ち、全体の反映が確定した送信内容を次の比較基準にする。
2. JSON はステージ識別子、編集範囲、セル寸法、取込元の配置スナップショットを識別する情報を持つ。セルは種別、座標、TileSet 参照、ソース ID、アトラス座標、代替タイル ID を保持する。シーンタイルも Godot のセル参照をそのまま保存する。マーカーは既存ノードの識別子と位置を保持する。チェックポイントは専用ブラシで追加・削除し、新規配置はセル下辺の中央に揃える。Godot では Checkpoints 配下に既存の checkpoint.tscn をインスタンス化する。
3. Godot 側の対応表で各種別を対応するノードへ振り分ける。たとえば地形は TerrainTiles、アンカーは GumAnchors、食べ物は Foods、開始・終了は PlacementMarkers 配下。未対応の種別は編集対象外とし、ステージにないレイヤーを貼り付けで暗黙に追加しない。
4. 反映前にステージ一致、取り込み後の競合、セル範囲、タイル参照、必須マーカーを検証し、差分の件数を表示する。検証を通過した配置と派生地形を Godot の一回の Undo 操作として反映し、シーン保存は通常の Godot 操作に委ねる。リビジョンが変わった場合は取り込み元・Godot 現在値・MapEdit 編集値を比較する。独立した編集だけを確認対象にし、同じ項目の異なる変更がある場合は場所を示して止める。取り込み元がない場合は明示確認で同名のない MapEdit チェックポイントだけを追加できる。
5. TerrainTiles の占有セルが変わったときは、対応する Terrain の静的矩形と、そのステージの地形輪郭を同期する。通常のステージ生成ツールによるシーン全体の再生成は使わない。片方向床、ガムアンカー、食べ物の物理設定は既存の Godot リソースで管理する。

## 初版の検証

- 対象は Time Attack（192×24）とレストラン（160×24）。両方に対し、Godot エディターの配置差分と履歴を `tools/verify_mapedit.gd` で検証する。
- 無編集の往復でセル ID、マーカー座標、編集対象外のノードが一致する。地形追加・削除が描画、衝突、ガム経路に一致し、Godot の Undo/Redo 一回で派生形状まで戻る。
- 競合、壊れた JSON、未知のタイル ID、別ステージへの貼り付けでは、既存シーンへの変更が一件も発生しない。ズーム後の配置、速いドラッグ、重複セルの消去は macOS の通常操作で確認する。


```sh
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --editor --path gd-bungee-gum --log-file /tmp/mapedit-check.log --script res://tools/verify_mapedit.gd
```
