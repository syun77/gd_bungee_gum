# 着地の土煙エフェクト案

Status: 土煙アセット・Godot接続とも実装済み。

## 作成済みアセット

`images/effects/landing_dust_{normal,heavy}.png` は192×128pxの透明RGBAアトラス。1セル64×32px、3列×4行、10フレーム（9表示＋透明終端）、30fps、0.30秒、足元ピボット(32,26)。末尾の未使用2セルも透明。JSONの終端時間は0msなので表示フレーム0～8を1/30秒ずつ再生して非表示にする。GIFは確認用に末尾へ待ち時間を追加している。

同名のJSON、`_contact.png`、`_preview.gif`、編集用`images/effects/landing-dust.mjs`を同梱。`heavy`オプションで強弱を切り替える。PixelFX coreのRng／fit／Painterを使うオリジナルの手続き描画で、画像や標準キャラクターの流用なし。ライセンス・通知は同フォルダのpixelfx-LICENSE.txt／pixelfx-NOTICE.md。

2回の連番レビューで煙の高さ・粒ごとの縮小率を調整。両種×4シードで境界逸脱なし・決定性・透明終端を検証し、PillowでRGBA寸法と全表示フレームを確認。実ゲームでのサイズ・着地同期は未確認。

## 見た目

足元から左右へ低く広がり、丸い煙の塊がほどけて消える短いピクセルアート。クリーム色の陶器床とコーラル／ミントの内装に合わせ、薄い暖色グレーを使用する。ガムのピンク発光と区別し、発光、ひび割れ、小石、床の変形は加えない。土の床専用の砂埃ではなく、アクションの接地を伝える記号として扱う。

- 初期案: 64×32px RGBA、足元ピボット(32,26)、30fps、0.30秒、非ループ。
- 通常着地: 実表示幅32～40px、高さ10～14px。強着地: 幅48～56px、高さ16～20px。サイズは実ゲーム倍率で確認して確定する。
- 候補色（暗→明）: #8F8582 / #B5AAA0 / #D7CCBA / #F0E6D2。外周は細く、影色の面積を抑える。床上で消える場合は中間色との明度差を先に調整する。
- 0～0.03秒: 両足の外側に低い塊が現れる。
- 0.03～0.10秒: 左右へ素早く広がる。左右各2～3個の丸い塊を少し非対称にする。
- 0.10～0.20秒: 横移動が減速し、少し浮いて塊が分離する。
- 0.20～0.30秒: 塊を小さく欠けさせて消す。透明度だけで消さず、輪郭の変化を残す。終了時は完全透明。

## PixelFX制作方法

ローカルの `pixelfx/src/fx/impacts/heavy-landing.js` の広がり・減速を参考に、専用 `landing-dust` を制作する。既存の176×80px／1.6秒の演出は通常着地には大きく長い。`act` のヒットストップやシェイク、標準ダミーはゲームへ持ち込まない。

`meta` と `draw(p,t,o)` を持つエフェクトとし、シード付き `Rng` で煙の位置・大きさ・遅延を固定する。左右の塊の軌道、成長、縮小を制御し、必要なら `Particles` / `P.DUST` を利用する。通常／強着地の2種類を同じ制作ソースから書き出す。強着地は粒数・広がりを増やし、単なる拡大による画素サイズの不一致を避ける。

制作・確認手順（pixelfxディレクトリ内）:

```sh
node tools/render.mjs impacts/heavy-landing --gif --no-actor
node tools/render.mjs impacts/landing-dust --gif --sheet --all --no-actor
node tools/check.mjs impacts/landing-dust
```

通常／強着地のオプションを分けて書き出す。白背景・暗背景の連番とGIFを確認した後、実ステージ背景とTetoを重ね、実表示倍率とカメラ縮小時を確認する。最初の0.1秒の読みやすさ、輪郭、消え際の順に修正する。

保存先: `images/effects/landing-dust.mjs`、`landing_dust_{normal,heavy}.png`、対応JSON・GIF・連番プレビュー。Godot用PNGは `gd-bungee-gum/assets/effects/` にコピー済みで、nearestで再生する。JSONのフレーム数・矩形・時間・ピボットを検証し、GodotのSpriteFramesまたは既存のエフェクト方式へ明示的に設定する。Aseprite形式JSONを標準Godotが自動読込する前提にしない。流用元に応じてMITライセンスと帰属を併記する。

## Godot接続

既存の `Player.simulate` は移動後に `not grounded and is_on_floor()` を検出し、着地ポーズを開始している。この確定した床接触遷移をイベント源とする。演出は物理へ力を加えず、Gameの固定ステップ順序を維持する。

- 床の接触点、支持面法線、接触直前の相対速度をイベントへ渡す。壁・天井は対象外。
- 強さの指標は `max(0, -(player_velocity_before_contact - surface_point_velocity).dot(normal))`。衝突で除去する前のプレイヤー速度を保存する。静的床の速度は0、回転する箱は接触点の並進＋回転速度を使う。
- しきい値: 80px/s未満は省略、80以上450未満は通常、450以上は強着地。共有設定のLanding Dustで変更できる。水平スイングの速さだけでは強着地にしない。
- 最初の床接触はスポーンの落ち着きとして省略。以後、非接地0.05秒以上かつ累積移動2px以上からの床接触遷移だけを通知し、圧縮回復と同じ更新は除外する。リスタートで状態を再生成する。
- Game直下の再利用Sprite2Dが0.30秒再生する。静的な床では接触地点へ残す。箱ではローカル接触点・法線を保存して移動／回転に追従し、箱消滅で終了する。再着地は先頭フレームから再生する。
- ピボットを床面に合わせ、ローカル上を支持面法線に揃える。床の下へ大きく描かない。足を隠さない低い輪郭を優先する。
- 着地ポーズ0.12秒の開始と同じ更新で再生する。物理停止やカメラシェイクは追加しない。

## 採用前の確認

通常のキック後の着地、ガムからの落下、高速の横向きスイング、角・一方通行床・移動／回転する箱で確認する。各着地で1回だけ発生し、待機・歩行・壁接触では発生しないこと。リスタート時に残らず、物理・ガムの挙動を変えないこと。透明終端・画像境界・決定性・ライセンスを確認する。`tools/verify_landing_dust.gd`で実Gameの着地・強弱・横速度・スポーン／接地揺れ／圧縮除外・追従・削除・再生終了を検証する。

## 実装ファイル

`player.gd`の`landed`シグナルを`Game._ready`から`LandingDustEffect.bind`へ接続。プレイヤーの物理更新内で衝突前速度を保存し、移動・接触確定後、剛体への反作用を適用する前にイベントを通知する。支持面法線は既存の矩形／TileMap面判定を共有する。`landing_dust_effect.gd`／`scenes/effects/landing_dust_effect.tscn`が3列×4行のPNGをnearest・原寸で描画し、ピボット補正は(-32,-26)。PNGとライセンス通知は`assets/effects/`に配置。Rの再起動要求時に即座に非表示にする。
