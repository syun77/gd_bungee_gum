# Godot実装計画

## 目的と位置付け

Godot 4系とGDScriptで、横視点2Dの短いステージを作る。まず1本のガムによる接着・張力・収縮・解除を完成させ、その同じ仕組みで移動、物体操作、物理弾の投げ返しを成立させる。

本書は全体の設計と合格条件を定義する。現在の実装範囲は `bungee-gum-prototype.md` を参照。単一接続・プレイヤー・物理箱は実装済みで、区画進行・投射物・クリア判定を含む全合格条件は未完了。ゲーム方針は `game-direction.md`、力学の要件は `physics-foundation.md`、ステージ構成は `stage-action-concept.md` に従う。Godotの具体的なマイナーバージョンはプロジェクト作成時に固定する。

## シーンと責務

```text
Game (Node)
├── StageRunner (Node2D): 区画生成・破棄、チェックポイント、クリア
│   └── Section (Node2D): 現在の区画シーン
│       ├── Terrain (StaticBody2D)
│       ├── Player (CharacterBody2D)
│       ├── Props (RigidBody2D群)
│       ├── ProjectileSpawner (Node2D)
│       └── Exit / Hazard (Area2D)
├── PhysicsCoordinator (Node): 固定更新の順序と接続管理
├── GumView (Node2D / Line2D): 接続と張力の描画
└── HUD (CanvasLayer): 照準、張力、再試行案内
```

- PlayerController: 意図速度、外部速度、接触、蹴り出し、衝突後の速度整理。
- GumConnection: 端点2個、自然長、張力、接続状態。移動用・攻撃用に分岐しない。
- GumEndpoint: 対象参照、対象ローカルの接着座標、世界座標と接着点速度の取得、力の受け渡し。
- GumSettings（Resource）: ばね係数、減衰、収縮速度、最小自然長、最大接続長、最大張力。
- Section: 初期配置と入口・出口。進行管理やガム計算を持たない。

接続は初期段階ではプレイヤーと対象の間の1本だけ。端点の設計は共通化するが、対象同士を接続する入力や複数接続は後回しにする。動的物体同士の作用反作用は専用の検証シーンで確認する。

## 接着と接続のルール

照準はマウスまたはスティックで指定し、接着入力を固定更新で処理する。レイは自分を除外し、地形と物体の両方を検出する。最初の衝突対象が接着不可ならそこで止め、奥の対象を選ばない。

命中座標は対象のローカル座標へ変換して保持する。毎ティック世界座標へ戻すことで、箱が移動・回転しても接着位置を追従させる。対象の削除、区画変更、最大長超過では安全に解除する。

接着時の自然長は現在の距離を基本とし、接着だけで突然大きな力を発生させない。収縮中のみ自然長を下限まで毎秒一定量短くする。収縮ボタンを離したらその長さを保持する。解除は接続を消すだけで、速度を変更しない。

初期試作ではロープの巻き付きは扱わない。端点間に地形が入ると遮蔽解除する。端点の接着面を誤って遮蔽と判定しないよう、接着点付近の許容距離と自己除外を設ける。視覚的に壁を貫くガムで引き続ける状態を避ける。

## 張力の計算

端点AからBへ向かう単位ベクトルを `n` とする。速度は中心速度ではなく接着点の速度を使う。回転する剛体では `v_point = v_center + omega × r` を用い、`r` は重心から接着点への世界座標の差とする。

```text
d = distance(A, B)
extension = d - rest_length
separation_speed = dot(v_B_point - v_A_point, n)

if extension <= 0:
    tension = 0
else:
    tension = clamp(k * extension + c * separation_speed, 0, max_tension)

F_A = n * tension
F_B = -F_A
```

弛んでいる間は減衰項も作用させない。伸びたときだけ引き、縮んだガムが対象を押し返さない。距離がほぼゼロなら方向計算を省略する。最大長は剛体的な距離拘束ではなく破断条件とし、瞬間移動で距離を修正しない。

剛体には毎物理ティック `apply_force(force, offset)` を使う。`offset` は剛体原点から接着点への世界方向の差で、ローカル座標をそのまま渡さない。接着点へ力を掛けることで回転も生じる。力へ `delta` を掛けてから `apply_force` へ渡さない。静的地形は固定端点として反力を受け持つ。

## プレイヤーの運動と衝突

`CharacterBody2D` はガムの力や重力を自動積分しないため、プレイヤーには計算用質量を定義する。

```text
external_velocity += (gum_force / player_mass + gravity) * delta
velocity = control_velocity + external_velocity
move_and_slide()
```

ここで `external_velocity` は運動量そのものではなく、運動量に対応する速度成分である。剛体とプレイヤーには同じ張力の逆向きの力を使うが、キャラクター制御を含むため世界全体の厳密な運動量保存を保証するモデルではない。

- 左右入力は control_velocity を加速度付きで調整し、external_velocity を上書きしない。
- 空中の入力加速度と抵抗は弱くし、接続解除後も振り子の接線方向へ進めるようにする。
- 衝突後は接触法線に向かう速度成分を除き、次ティックへ壁向きの外部速度を持ち越さない。意図速度も同じ法線で整理し、両成分の和を衝突後の `velocity` と整合させる。移動足場から得る速度は二重加算しない。
- 張力そのものは壁に接触していても残り得る。壁へ速度だけが蓄積する不具合と区別する。
- 床・壁・天井への接触法線に沿って短い蹴り出しを加える。長押しや空中連打で再発動させず、接触から離れて再接触するまで同じ蹴り出しを繰り返せないようにする。
- 蹴り出し単体では最初の必須ギャップを越えられない寸法にし、ガム移動を必須にする。

プレイヤーと剛体の通常接触は、ガムの相互作用とは別の検証項目とする。重い箱がプレイヤーに押されただけで軽く動かないか、壁際で挟まれないかを確認し、追加の押し出し処理を入れる場合はエンジンの接触応答と二重に適用しない。

## 固定更新と描画

60物理ティック毎秒から始める。入力取得・接続操作 → 端点状態の取得 → 張力計算と双方への力の受け渡し → プレイヤー移動 → 表示用状態の保存、の順序をCoordinatorから明示的に呼ぶ。各ノードが独立してプレイヤーや接続を二重更新しない。剛体の積分と衝突はエンジンに任せる。

ガムの描画は物理計算から分離する。弛みは曲線、張力は線の太さ・色・音程で伝える。照準対象、接着点、張力上限への接近も表示する。見た目の曲線は衝突判定や力計算へ使わない。物理補間を導入するときは線の端点も本体と同じ表示時刻にそろえる。

調整用に自然長、距離、張力、両端点速度、プレイヤーの意図速度と外部速度、破断理由を表示できるようにする。

## 物理パズルとステージ

| 区画 | 内容 | 確認する遊び |
| --- | --- | --- |
| 1 | 安全な床と壁で蹴り出す | 接触と操作の理解 |
| 2 | 天井へ接着して谷を越える | 振り子と解除タイミング |
| 3 | 軽い箱を引いて足場にする | 相手を動かす、配置を変える |
| 4 | 重い箱をアンカーにして谷を越える | 質量差で自分が動く |
| 5 | 遅い物理弾を接着し、収縮・解除して標的へ返す | 同じ力学を攻防へ使う |
| 6 | 習得した移動で出口へ到達する | 区画進行、クリア、再試行 |

箱は同じシーンの質量違いで作る。投射物も `RigidBody2D` とし、返す方向や速度を専用の反射処理で上書きしない。標的は実際の命中を検出する。最初は大きい標的と遅い弾で、接着可能な時間を確保する。

重い箱も空中では落下するため、アンカー区画では安定した床や受け止める地形を用意する。箱が軽い／重いというラベルだけで固定可否を決めない。

区画リスタートは接続を破棄して現在のSectionを初期シーンから再生成する方式とする。箱、弾、タイマー、スイッチ、速度も初期化され、物理状態の部分的な巻き戻しを避けられる。シーン破棄・再生成は衝突通知中に直接行わず遅延実行し、重複リスタート要求をまとめる。

## 実装順と合格判定

1. **物理実験室**: 壁、天井、プレイヤー、質量の異なる箱、ガムとデバッグ表示だけを作る。振り子、収縮、解除、作用反作用を確かめる。
2. **操作感**: 衝突後の速度整理、蹴り出し、照準、張力表示を調整する。自由ジャンプなしで移動が成立するまでステージ量産へ進まない。
3. **6区画の灰色箱ステージ**: 仮の図形だけで区画、物理弾、出口、再試行を完成させる。
4. **安定性とプレイ検証**: 最大伸長、壁への収縮、回転する接着先、接続先削除、繰り返しリスタートを確認する。問題を解消してから絵、音、敵の種類を増やす。

合格の証拠として、同じ初期配置からの入力列と張力・速度ログを残す。完全な環境横断の決定論は要求しない。

- 軽い箱では箱側、重い箱ではプレイヤー側が大きく加速する。
- 弛み状態の張力はゼロ。移動する端点同士の力の和は丸め誤差を除きゼロ。
- 解除処理だけでは速度が変化しない。重力や衝突による次ティックの変化とは分けて検証する。
- 壁へ収縮し続けても、解除後に蓄積した隠れた速度で飛び出さない。
- 30/60/144描画fpsで60物理ティックを維持し、入力に対する軌道を比較する。実際に物理更新が追いつかない過負荷も別に確認する。
- 高速な物理弾ではCCDを評価し、薄い壁の通過を調べる。改善しなければ速度・衝突形状・物理ティック設定を調整する。
- 物理補間のオン／オフを操作遅延と端点表示の両面で比較する。
- 各区画が通常ジャンプや特定座標へのワープなしでクリアできる。

ばねの強さだけで解決しようとせず、自然長、収縮速度、減衰、質量比、地形の順に原因を切り分ける。値はResourceで管理し、試作の測定前に最適値として固定しない。

- [RigidBody2D](https://docs.godotengine.org/en/stable/classes/class_rigidbody2d.html): 継続的な力、接着点への力、CCD。
