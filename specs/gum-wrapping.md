# バンジーガムの角への巻き付き設計

## 位置付けと範囲

障害物との交差を、静的地形の角を経由する接続へ変換する設計とする。本書は巻き付きの目標仕様であり、ランタイムは未実装。現行動作は `bungee-gum-prototype.md` に記載する。入力は `keyboard-controls.md`、物理責務は `physics-foundation.md` に従う。

1本の接続、元の接着対象とローカル接着点、Zによる解除、Xによる収縮／緩めを維持する。支点は新しい接着ではなく、摩擦のない地形上の案内点である。収縮量は接続全体に作用し、支点ごとの別々のばねや長さ固定は作らない。

初期実装は動かない多角形地形の凸角を対象とする。現在のTerrainの矩形群を合成した外周を使用する。動的箱への接着と力・回転は維持するが、箱の角への巻き付きは初期範囲に含めない。複数の接続、ロープ自体の質量・自己衝突、摩擦による支点での張力差、円形障害物は対象外。

## プレイヤーから見えるルール

- ガムが地形の角に掛かると接続を維持したまま経路が曲がり、プレイヤーは最も手前の支点へ引かれる。
- 接着点は付け替わらず、経路は `プレイヤー → 支点0 → … → 支点N → 接着点` となる。
- 角への引っ掛かりが解ければその支点を除く。緩めたことだけでは全支点を消さない。
- 距離・自然長・緩め余裕・最大長は経路全体について扱う。各区間が900 px以内でも合計が900 pxを超えれば最大長解除になる。
- 発射は従来の直線レイ。壁の奥へ回り込む自動照準や初回接着は行わない。
- 地形交差だけでは切断しない。Z、最大長超過、対象喪失、リスタートと、後述の経路生成不能は解除理由となる。

## 地形データ

`GumTerrainGeometry` が物理衝突形状を入力に外周と角の安定IDを作る。タイルの装飾・見た目の縁線を使わない。現在の同一Terrain内の矩形は和集合を取り、共有辺・内部角・重複辺を除去する。離れた足場と穴の輪郭は別ループとして保持する。

各角に輪郭ID、頂点ID、前後の辺、固体側、外側へ逃がした案内座標を持つ。自由空間に向く凸角だけを候補にし、凹角を独立した支点にしない。判定用の経路には初期値1 pxのクリアランスを設ける。接着端点は本来の衝突面座標を保持し、端点付近の許容はその面だけへ限定する。同じTerrain全体をレイから除外してはならない。

未対応形状や動く地形は、巻き付き対応のように黙って登録しない。ステージ検証でエラーにし、対応形状に直す。地形更新は輪郭再生成と経路の再検証を同じ固定更新の境界で行う。

## 経路の状態と追加

`GumPath` は端点と順序付き支点、各支点の巻き側、前ティックの端点／経路を保持する。同じ状況で同じ結果を得るため、同距離候補は安定ID順で選ぶ。

1. 既存経路を基準に、前ティックからの端点移動で各区間が掃く領域と現在区間の交差を検出する。現在のレイだけで判定し、高速移動で角を飛び越すことを許さない。
2. 交差した区間について、最初に接触した外周を特定する。交差点そのものではなく、その障害物の角を経由する局所経路を作る。
3. 外周上の候補角と区間両端の可視グラフを作り、固体内部を横切らず、移動履歴の巻き側と既存の障害物回避側を保つ経路の中で最短を選ぶ。全マップの最短経路を毎回取り直して反対側へ飛び移らない。
4. 必要なら一度に複数の角を挿入し、全区間を再検証する。長い矩形を横断する場合は入口側の1角だけで解決したとみなさない。
5. 追加で自然長、速度、接着点、制御モードを変更しない。力は解決後の経路から求める。

接着対象自身の別の面も障害物とする。静的接着ならその外周に巻ける。プレイヤーと対象の双方の移動で交差し得るため、プレイヤー側区間だけを調べない。

## 支点の解除と安定性

各支点の直前点と直後点を直接結べるか調べる。短絡区間にクリアランスを持った可視性があり、元の巻き側から外れる方向へ移動して接触角を解消したときに支点を外す。距離が短くなるだけでは外さない。

初期調整値として、追加判定1 pxに対し解除は2 pxの離隔を2ティック連続で満たすヒステリシスを使う。反対の障害物が短絡区間を遮る場合は解除しない。同じティック内で同じ支点の追加と解除を繰り返さない。複数支点の除去は順序を固定し、除去ごとに残りの区間を再検証する。

経路は張力ゼロでも障害物回避のため保持する。実際の弛んだロープが落下して別の角に載るシミュレーションは行わない。支点の追加・解除そのものからインパルスを発生させず、減衰のために前後の経路長差を速度として使わない。

## 張力と反力

点列を `q[0] = A, q[1] … q[m] = B`、区間方向を `u[i] = normalize(q[i+1] - q[i])` とする。静的支点の速度はゼロ。Bの速度は剛体の回転を含む接着点速度、Aはプレイヤーの物理起点速度を使う。

```text
path_length = sum(length(q[i+1] - q[i]))
path_speed = sum(dot(v[i+1] - v[i], u[i]))
extension = path_length - rest_length
T = 0 if extension <= 0 else clamp(k * extension + c * path_speed, 0, maximum_tension)
F_A = T * u[0]
F_B = -T * u[m-1]
F_terrain_at_pivot[i] = T * (u[i] - u[i-1])  # 1 <= i < m
```

曲がった経路では両端の力の大きさは等しいが、世界座標での向きは単純な正反対ではない。地形へ伝わる各支点の力を加えると全体の合力がゼロになる。静的地形がその反力を受け持つ。支点なしでは従来の等大逆向きの力へ一致する。動的な支点へ拡張する場合は、この支点力と接触点でのトルクも剛体へ渡すことを必須とする。

Playerへの積分、RigidBody2Dの接着点へのapply_force、衝突後の外部速度整理、解除後の運動量保持は従来の責務を使う。位置を角の周りの円へ直接補正しない。極短区間は重複点を整理してゼロ除算を避け、端点同士が近い場合も残った経路全体で判定する。

収縮は全体のrest_lengthを毎秒180 pxで下限36 pxまで短縮する。緩めは `min(maximum_length, max(rest_length, path_length + loosen_margin))` へ一度だけ延長し固定する。角の追加によって自然長を自動延長しない。射程900 pxと最大経路長900 pxは別の概念としてコード内で区別し、初期値は共有設定maximum_lengthを使う。

## 固定更新と安全策

Gameの更新は、リスタート／対象有効性 → Z優先の入力処理 → 経路解決 → 経路長上限確認 → 収縮・張力計算 → Player移動 → 表示とする。移動で生じた交差は次ティックの掃引で解決し、そのティックの張力より前に反映する。描画で経路を変更しない。

初期予算は支点16個、経路修正32回／ティック。範囲内の正しい地形交差は切断しない。予算超過、端点が固体内部に残って回復不能、未対応動的障害物との交差で有効な経路を作れない場合は、そのティックの力を適用せず `PATH LIMIT` / `PATH INVALID` / `UNSUPPORTED OBSTACLE` で安全解除する。壁を貫く力を代用しない。開発時は障害物IDと失敗種別を記録し、通常ステージでは受け入れテストによりこれらを発生させない。

動的箱が経路を横切った場合の `UNSUPPORTED OBSTACLE` は初期実装の明示的な制限である。箱越しの貫通力を許す仕様ではない。動的巻き付きの完成前に、箱を支点にすることが必須のステージは作らない。

削除された支点は再経路探索し、有効な経路を作れれば維持する。接着対象そのものの削除はTARGET LOST、経路全長超過はTOO FARとする。Zは経路と支点を即時消去し、同ティックの張力を適用しない。

## 表示とGodot構成

物理経路と描画経路は同じ支点列を使う。支点を小さな点で示し、HUDに総経路長／自然長／最大長比と支点数を表示する。物理起点とアニメーション手先の差は最初の描画区間だけで吸収する。弛みの装飾曲線が地形を貫く場合はたわみ量を減らし、それでも回避できなければ折れ線表示にする。

- `gum_connection.gd`: 接着対象、モード、自然長、張力と力の適用を所有。
- `gum_path.gd`: 経路の追加・解除、経路長・長さ変化速度・区間方向を返す。外力や入力は扱わない。
- `gum_terrain_geometry.gd`: 実衝突形状から外周、可視性、掃引候補を提供。ステージ生成器の矩形定義を複製しない。
- `game_settings.gd`: 巻き付きのクリアランス、解除離隔／確認ティック、支点／修正上限をInspectorへ追加する。

## 実装順序と合格条件

1. 地形の和集合外周と安定角IDを生成。現在の保存済みマップで内部共有辺に支点が生じないこと、全候補が物理形状と一致することを検証する。
2. 1矩形への巻き付き・解除を経路単体で実装。上下左右から進入し、角1個／2個、同一Terrain内の別面、凹形状、穴、複数足場を確認する。
3. 経路全長の張力へ統合。支点なしの既存テストを維持し、曲がった経路の両端力＋地形反力の和、各区間の長さ変化速度、動的接着点の質量差・回転を数値検証する。
4. 高速な両端移動の掃引と複数支点、解除ヒステリシスを検証。角すれすれの静止／往復300ティックで支点の増殖・左右の経路反転・NaN・張力上限超過が起きないこと。経路変更だけで減衰の異常ピークが生じないこと。
5. Xの緩めで総経路長＋32 pxになること、再収縮、支点ありのZで速度保持、900 px超過、対象削除、地形削除、各安全予算と未対応動的障害物の解除理由を確認する。
6. 実Gameで足場の下への回り込み、角支点の振り子、複数角からの巻き戻し、箱を地形越しに引く動作と衝突、瞬間リスタートを確認。30／60／144描画fpsで固定更新の結果を比較し、全区画で性能を測定する。

`verify_gum.gd`の遮蔽による切断テストを巻き付き維持へ変更し、経路専用の `verify_gum_path.gd` を追加する。`verify_controls.gd`、`verify_player.gd`、`verify_theater_stage.gd` を併走する。実装完了時には現行動作文書、HUD、設定、テストを同時に更新し、遮蔽切断との混在を残さない。
